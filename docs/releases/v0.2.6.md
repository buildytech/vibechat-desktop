## 0.2.6

Project tools are isolated from secrets; host limits, firewall and snapshots. / Инструменты проекта изолированы от секретов; лимиты хоста, firewall и снимки.

### New / Новое

- Container limits follow the host: `min(2, nproc)` CPUs and 75% of memory up to 4 GiB; a 2 GiB swap file is added when the host has no swap. Preflight counts that swap and reports CPUs. / Лимиты контейнера считаются по хосту: `min(2, nproc)` CPU и 75% памяти, не больше 4 ГиБ; если на хосте нет swap, добавляется файл на 2 ГиБ. Preflight учитывает этот swap и сообщает число CPU.
- Daily container snapshots, kept 7 days. / Ежедневные снимки контейнера, хранятся 7 дней.
- The container's apt uses HTTPS (`deb.debian.org` is on the egress allowlist) with unattended-upgrades. / apt в контейнере идёт по HTTPS (`deb.debian.org` в списке egress) и с unattended-upgrades.
- When the system has no Node.js, `node` is Bun (`sandbox.EnsureNode`), so the template checks that start with `#!/usr/bin/env node` (`ui8px` in `lint:px`, `ui8kit`, `svelte-check`) run for the agent and `verify` in the container. / Если в системе нет Node.js, `node` — это Bun (`sandbox.EnsureNode`), поэтому проверки шаблона с `#!/usr/bin/env node` (`ui8px` в `lint:px`, `ui8kit`, `svelte-check`) работают у агента и в `verify` в контейнере.
- An agent run's error goes to the log. / Ошибка запуска агента пишется в лог.

### Security / Безопасность

- `bun install` runs with `--ignore-scripts`, and it and the Vite dev server run in a bubblewrap jail: the system is read-only; the data folder with secrets, auth and other projects is replaced by an empty tmpfs; only the project and the Bun cache are writable; the jail has its own PID namespace so the bridge's `/proc` is closed; the environment is allowlisted instead of `os.Environ`. / `bun install` идёт с `--ignore-scripts`, он и dev-сервер Vite работают в jail bubblewrap: система только для чтения; каталог данных с секретами, auth и другими проектами заменён пустым tmpfs; писать можно только в проект и кэш Bun; свой PID namespace, поэтому `/proc` бриджа закрыт; окружение — белый список, а не `os.Environ`.
- The packaged service requires the jail (`VIBECHAT_TOOLS_ISOLATION=require`); `doctor` checks it (`tools`). / Собранный сервис требует эту изоляцию (`VIBECHAT_TOOLS_ISOLATION=require`); `doctor` проверяет её (`tools`).
- Lockdown adds a host inbound filter (nftables, its own table: SSH ports, ICMP, DHCP answers on the default-route interfaces, the rest dropped; the same rollback timer removes it unless the app's new key login works) and turns off LLMNR/mDNS in systemd-resolved. / Lockdown ставит входящий фильтр на хосте (nftables, своя таблица: порты SSH, ICMP, ответы DHCP на интерфейсах маршрута по умолчанию, остальное отбрасывается; тот же таймер отката снимает его, если вход по новому ключу приложения не подтверждён) и выключает LLMNR/mDNS в systemd-resolved.
- The key diagnostic names only a known public prefix and a SHA-256 fingerprint (no first or last characters). / Диагностика ключа показывает только известный публичный префикс и отпечаток SHA-256 (без первых и последних символов).

To update the server: `sudo vibechat-server update`. Check every asset against this release's `SHA256SUMS` (the server's self-update does the same for the `.deb` before `dpkg -i`).
Обновление сервера: `sudo vibechat-server update`. Сверьте файлы с `SHA256SUMS` этого релиза (самообновление сервера так же проверяет `.deb` перед `dpkg -i`).
