## 0.2.12

A second coding agent for the Russian contour: Pi with a model provider you choose, in a jail with no secrets and no network for its shell. Cursor stays the default and is unchanged. / Второй кодовый агент для российского контура: Pi с выбираемым провайдером моделей, в изоляции без секретов и без сети для его shell. Cursor остаётся по умолчанию и не меняется.

### Added / Добавлено

- **Pi runtime next to Cursor (opt-in, server side).** A server runs Pi instead of the Cursor SDK only when `contour.json` in the data folder says `"runtime": "pi"`; without that file nothing changes. The config holds no keys: the provider key is an environment variable of the service (for example `VIBECHAT_OPENROUTER_KEY` in a root-only `EnvironmentFile`). Existing chats keep the runtime they started with. `vibechat-server doctor` checks the contour (bubblewrap, the nested shell jail, Node, the pinned Pi, the key) and `vibechat-server egress-domains` prints the one host the contour needs. / **Pi рядом с Cursor (по желанию, на стороне сервера).** Сервер запускает Pi вместо Cursor SDK только если в `contour.json` в папке данных указано `"runtime": "pi"`; без этого файла ничего не меняется. В конфиге нет ключей: ключ провайдера — переменная окружения сервиса (например `VIBECHAT_OPENROUTER_KEY` в `EnvironmentFile` только для root). Существующие чаты остаются на своём рантайме. `vibechat-server doctor` проверяет контур (bubblewrap, вложенную изоляцию shell, Node, закреплённый Pi, ключ), а `vibechat-server egress-domains` печатает единственный нужный контуру хост.
- **Providers are configuration.** Any OpenAI-compatible endpoint (OpenRouter, gpt-oss on a Russian cloud, a vLLM gateway) is one `openai` block: base URL, key variable, auth header and scheme, fixed headers, quirk flags, models. Yandex AI Studio and GigaChat are presets (tool-call ids made unique for Yandex; GigaChat tools↔functions translated, stub-tested only). / **Провайдеры — это конфигурация.** Любой OpenAI-совместимый endpoint (OpenRouter, gpt-oss в российском облаке, шлюз vLLM) описывается блоком `openai`: адрес, переменная ключа, заголовок и схема авторизации, фиксированные заголовки, флаги особенностей, модели. Yandex AI Studio и GigaChat — пресеты (для Yandex id вызовов инструментов делаются уникальными; GigaChat tools↔functions переводится, проверено только на заглушке).
- **Isolation of the agent.** Pi runs in a bubblewrap jail with its own empty network: the model is reached only through a per-run Unix socket to a host-side gateway, which adds the provider key; no key and no token exist in the jail. The agent's shell runs in a nested jail with no network at all, its own process list, and without the socket or the agent's folders. If the jail cannot be built, the agent does not start. / **Изоляция агента.** Pi работает в jail bubblewrap со своей пустой сетью: к модели он обращается только через сокет Unix на одну сессию к шлюзу на стороне хоста, который добавляет ключ провайдера; ни ключа, ни токена в jail нет. Shell агента работает во вложенном jail без какой-либо сети, со своим списком процессов и без сокета и папок агента. Если jail собрать нельзя, агент не запускается.
- **Git in the agent's jail.** `git status`, `add` and `commit` work in session worktrees and in the project folder; the repository's config and hooks are read-only there. / **Git в jail агента.** `git status`, `add` и `commit` работают в рабочих копиях сессий и в папке проекта; конфиг и хуки репозитория там только для чтения.

### Fixed / Исправлено

- **Host git no longer runs programs an agent wrote.** The agent can write its worktree; a `.git` folder or `commondir` it replaced, with a config naming `core.fsmonitor` (or a filter or merge driver), made the server's next `git status` run that program outside the sandbox. The server now restores a worktree's git files before using git there, refuses a repository whose config can run a program, and switches such settings off on every git command. This applies to every agent runtime. / **Git на хосте больше не запускает программы, написанные агентом.** Агент может писать в свою рабочую копию; подменённая им папка `.git` или `commondir` с конфигом, называющим `core.fsmonitor` (или фильтр, или драйвер слияния), заставляла следующий `git status` сервера запустить эту программу вне песочницы. Теперь сервер перед работой с git восстанавливает git-файлы рабочей копии, отказывается работать в репозитории с конфигом, способным запускать программы, и отключает такие настройки в каждой команде git. Это касается любого рантайма агента.

### Upgrade note / Обновление

Server: `sudo vibechat-server update`. Nothing changes until a `contour.json` with `"runtime": "pi"` exists. Pi needs Node 22.19+ and the pinned Pi (`fetch-pi`), Linux and bubblewrap. The desktop app is unchanged apart from its version. / Сервер: `sudo vibechat-server update`. Ничего не меняется, пока нет `contour.json` с `"runtime": "pi"`. Для Pi нужны Node 22.19+ и закреплённый Pi (`fetch-pi`), Linux и bubblewrap. Приложение для компьютера не изменилось, кроме номера версии.

Check every asset against this release's `SHA256SUMS`. / Сверьте файлы с `SHA256SUMS` этого релиза.
