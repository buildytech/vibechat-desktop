## 0.2.13

Cloud.ru GigaChat-4 for the Pi contour, and a contour can now offer models of several providers, the first one being the default. / GigaChat-4 от Cloud.ru для контура Pi, и контур теперь может предлагать модели нескольких провайдеров, первый из которых — по умолчанию.

### Added / Добавлено

- **Several providers in one contour.** The `openai` key of `contour.json` takes one block as before or an array of blocks. The model menu follows the list and the first model is what a new chat runs; each request goes to the provider that owns its model, with that provider's own key, headers and model name. A provider whose key is missing refuses only its own models. `vibechat-server egress-domains` prints the hosts of all providers; `doctor` reports each provider's key on its own line. An example is in `docs/contours/ru-cloudru-openrouter.json` (Cloud.ru GigaChat-4 first, OpenRouter second). / **Несколько провайдеров в одном контуре.** Ключ `openai` в `contour.json` принимает один блок, как раньше, или массив блоков. Меню моделей повторяет список, а первая модель — та, на которой запускается новый чат; каждый запрос уходит провайдеру, которому принадлежит его модель, с его ключом, заголовками и названием модели. Провайдер без ключа отказывает только в своих моделях. `vibechat-server egress-domains` печатает хосты всех провайдеров, `doctor` показывает ключ каждого провайдера отдельной строкой. Пример — `docs/contours/ru-cloudru-openrouter.json` (сначала GigaChat-4 от Cloud.ru, затем OpenRouter).
- **Cloud.ru Foundation Models** (`https://foundation-models.api.cloud.ru/v1`, OpenAI-compatible, Bearer) is a configuration block, no provider code. Checked with the real Pi: a three-step chat (create a file, edit it, run it in the shell) passes, with and without echoing the provider's `tool_state_id`; its `reasoning` stream shows as thinking. / **Cloud.ru Foundation Models** (`https://foundation-models.api.cloud.ru/v1`, OpenAI-совместимый, Bearer) — это блок конфигурации, без кода провайдера. Проверено на настоящем Pi: трёхшаговый чат (создать файл, изменить, запустить в shell) проходит и с возвратом `tool_state_id` провайдера, и без него; поток `reasoning` показывается как размышления.
- **Two generic provider options.** `quirks.echoFields` lists message fields outside the OpenAI format that a provider returns with a tool call and wants back (the gateway carries them inside the tool-call ids and restores them on the next request; only the named fields, only plain values). `body` presets extra request fields such as `{"provider":{"sort":"price"}}`; a field the agent's request has wins. / **Два общих параметра провайдера.** `quirks.echoFields` перечисляет поля сообщения вне формата OpenAI, которые провайдер присылает вместе с вызовом инструмента и ждёт обратно (шлюз переносит их внутри id вызова и восстанавливает в следующем запросе; только названные поля и только простые значения). `body` задаёт дополнительные поля запроса, например `{"provider":{"sort":"price"}}`; поле из запроса агента имеет приоритет.

### Upgrade note / Обновление

Server: `sudo vibechat-server update`. Existing `contour.json` files keep working unchanged; nothing changes without one with `"runtime": "pi"`. A provider's key is an environment variable of the service (`VIBECHAT_CLOUDRU_KEY`, `VIBECHAT_OPENROUTER_KEY`), and its host must be open in the container's egress list. The desktop app is unchanged apart from its version. / Сервер: `sudo vibechat-server update`. Существующие `contour.json` работают без изменений; без файла с `"runtime": "pi"` ничего не меняется. Ключ провайдера — переменная окружения сервиса (`VIBECHAT_CLOUDRU_KEY`, `VIBECHAT_OPENROUTER_KEY`), а его хост должен быть открыт в списке исходящих адресов контейнера. Приложение для компьютера не изменилось, кроме номера версии.

Check every asset against this release's `SHA256SUMS`. / Сверьте файлы с `SHA256SUMS` этого релиза.
